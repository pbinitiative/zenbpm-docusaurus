# ZenBPM – v0.1.0

## Features

- Released the first version of ZenBPM, a BPMN 2.0 engine written in Go. This early release was not yet intended for production use.
- Added execution of core BPMN elements:
  - start and end events, service tasks, and user tasks (handled as service tasks),
  - exclusive, inclusive, parallel and event-based gateways, including default flows,
  - intermediate catch and throw events, message throw events, timer events and call activities.
- Added a token-based execution model, with protection against running the same process instance in parallel.
- Added a first DMN engine with decision table evaluation, decision storage and FEEL expressions through the `pbinitiative/feel` library.
- Added clustering: several nodes can form a ZenBPM cluster, with partition state propagation, leadership checks, and restarts without data loss.
- Added durable storage on rqlite, with a persistence layer generated with sqlc and an in-memory storage option for tests.
- Added incident persistence, so incidents can be read and resolved.
- Added flow element history for process instances.
- Added an LRU cache for process definitions, with configurable persistence settings.
- Added a public REST API and a first gRPC API for process management and system integration.
- Added OpenTelemetry metrics and tracing.
- Added a Dockerfile, an example showcase process, end-to-end tests, and the first documentation, published as a separate Docusaurus project.

## Fixes

- Fixed inclusive and exclusive gateway flow selection.
- Fixed intermediate catch events when several process instances run at the same time.
- Fixed job input mapping and message throw event parsing.
- Fixed the timer manager closing the same channel more than once.
- Fixed graceful shutdown of the engine.
