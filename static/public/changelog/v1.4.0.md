# ZenBPM – v1.4.0

## Features

- Added receive tasks.
- Jobs now carry separate `inputVariables` and `outputVariables` instead of a single `variables` field.
- Renamed the BPMN extension namespace prefix from `zeebe` to `zenbpm` in the modeler, parser and documentation.
- Added static code analysis (SAST) to the build.
- Removed runtime `panic` calls outside startup and structured the remaining goroutines. Panics are kept only where failing fast at startup is intended.
- Increased test coverage for exclusive, parallel, inclusive and event-based gateways, link intermediate catch events and error boundary events.

## Fixes

- Deploying a BPMN model with unsupported element types now returns HTTP **400**.
- Message and timer intermediate events are included in history.
- Parallel gateway joins handle repeated activations correctly.
- Fixed security vulnerabilities in the Docker image by updating the Go toolchain to **1.26.4**.

## Breaking Changes

- The job `variables` field in the REST and gRPC APIs was replaced with `inputVariables` (provided when the job is created) and `outputVariables` (set when the job completes or fails). Update workers and clients that read `variables`.
- Process models are now written with the `zenbpm` extension namespace prefix. Models using the legacy `zeebe` prefix continue to be parsed.
- BPMN models containing unsupported elements are rejected at deployment with HTTP **400**.
