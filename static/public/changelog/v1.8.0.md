# ZenBPM – v1.8.0

## Features

- Added whole-cluster backup and restore for highly available deployments.
  - `GET /system/v1/cluster/backup` can be called on any node and streams a point-in-time snapshot of every partition as a single tar archive, with no external storage required and no interruption to traffic.
  - `POST /system/v1/cluster/restore` restores a backup on the cluster leader, either onto an empty cluster or, with `?force=true`, over an existing one.
  - Each restore is tracked as a restore operation with phases, status and a lease, exposed through `/system/v1/cluster/restore/operations` and `/system/status`, and can be aborted.
  - During a restore the cluster is gated: mutating calls are rejected, engines are stopped and partition writes are fenced, so application writes cannot race with the restore.
  - After loading, a reconciliation step repairs snapshot skew between partitions by syncing missing definitions and rebuilding message-subscription pointers.
  - Timeouts, size limits and the spool directory are configurable under `cluster.restore.*`.
- Added protection against infinite execution loops in process instances.
  - `maxProcessInstanceNestingDepth` (default **100**) limits the depth of parent→child instance chains created by call activities, subprocesses and multi-instance bodies.
  - `maxProcessInstanceFlowNodeCount` (default **10000**) limits the total number of flow node executions within one process instance.
  - Exceeding a limit stops execution and raises an incident describing the potential loop. Resolving a flow-node-count incident resets the counter and grants a fresh execution budget.
- Added process version selection in call activities: `zenbpm:calledElement` now accepts an exact numeric `version`, or `bindingType="versionTag"` with a `versionTag`, in addition to the default `latest`.
- Added configurable job types for user tasks through the optional `zenbpm:taskDefinition type="..."` element, so workers can filter and consume user-task jobs by type. The default remains `user-task-type`.
- Added `zenbpm:output` mappings on start events: none and timer start events can initialize or derive root process variables, and message start events can map selected values from the message payload.
- Added formatting-insensitive redeployment of BPMN and DMN resources: redeploying a file whose only changes are formatting (whitespace, attribute order) no longer creates a new process or decision version.
- Improved performance by reusing compiled FEEL programs, and fixed script runtime lifecycle leaks in the BPMN and DMN engines.
- Event subscription endpoints now return subscriptions in every state when no state filter is given.
- Updated core dependencies, including rqlite, gRPC, OpenTelemetry, Sentry and protobuf.

## Fixes

- Fixed DMN redeployment so that deduplication compares against the latest validated definition, and deploying A, then B, then A again creates a new version instead of reusing an older key.
- Fixed handling of the legacy empty `<nil>` assignee value and improved job assignment for user tasks.
- Fixed and corrected internal documentation links.

## Breaking Changes

- BPMN and DMN deployments now send the file contents directly as the request body with `Content-Type: application/octet-stream`. Multipart uploads for `POST /v1/process-definitions` and `application/xml` uploads for `POST /v1/dmn-resource-definitions` now return `415 Unsupported Media Type`. With curl, replace `-F "resource=@process.bpmn"` with `-H "Content-Type: application/octet-stream" --data-binary @process.bpmn`.
- The Go client's `CreateProcessDefinitionMultipartBody` and `CreateProcessDefinitionMultipartRequestBody` types were removed. Use `CreateProcessDefinitionWithBodyWithResponse` or `CreateDmnResourceDefinitionWithBodyWithResponse` instead.
- The new loop-protection limits are enabled by default. Process instances that legitimately execute more than **10000** flow nodes, or nest deeper than **100** levels, now raise an incident. Raise the limits, or set a value of 0 or less to disable a check. For existing instances, counting starts at zero when the upgrade is applied.
- Redeploying a BPMN or DMN file that differs only in formatting no longer creates a new version. Deployment pipelines that relied on every deploy producing a new version should change the model content or the version tag.
- Event subscription listings without a state filter now include subscriptions in every state, not only active ones. Pass a state filter to keep the previous behaviour.
- Workers holding job keys from before a cluster restore receive `404 Not Found` when completing or failing those jobs, because the restored data no longer contains them.
